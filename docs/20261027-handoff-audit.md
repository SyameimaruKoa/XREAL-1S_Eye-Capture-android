# 引継書の照合結果（2026-10-27）

## 照合対象と範囲

- 会話ログ `xreal-1s-eye.json` のユーザー発言16件、記録された質問への回答、および関連する助手の報告。
- 録画アプリ用 `HANDOFF.md`、`NEXT_AI_GOALS.md`、現在のソース、Git、端末と録画の一部。
- `.research/xreal-linux/docs/handoff.md` は別の Linux / SteamVR プロジェクトの引継書で、Android 録画アプリの現在状態を示すものではない。デバイスへの状態変更について同資料に記載された制約は、該当する操作の前に確認する。
- 会話には多数のツール出力と長い推論が含まれる。ユーザーの指示や回答は助手の推測と区別し、この照合結果も全ツール出力の完全な監査ではない。

## 重要な訂正

1. **音声要件**: 当初の最低要件は XREAL 内蔵マイクによる独立した2chステレオ、可能なら4ch。記録された質問へのユーザー回答は「B>>>D NG=A＆C」で、助手も B（SDK 等の独立音声経路探索）優先、D（モノラルへの要件変更）は次点、デュアルモノを独立2chとして扱う案 A と外部マイク案 C は不可と受け取っている。現アプリは 1ch AAC を保存するが、それだけで独立2chの元の目標を満たしたわけではない。引継書の「B は不可で確定」は調査したライブラリ等の範囲を越えた断定であり、別経路全体が不可能と証明されていない。ユーザーは後から UVC/UAC を通らない音声経路の探索も明示的に依頼している。
2. **既存録画アプリ**: 当初の明示要件は、条件を満たす無変換録画が既存アプリで可能なら専用録画エンジンを作らず、UVC 以外の無変換経路も検討すること。過去の助手は既存アプリ評価を未実施と報告している。録画アプリの実装が存在することは、既存アプリの比較完了を意味しない。
3. **映像と加工方針**: 右端と緑線の性質は実測されているが、信号の発生源や左端に本来存在する画素の復元は未確定。「有効画像 2016×1512」「Eye の FOV が原因」などは確定事項として扱わない。2026-10-27 のユーザーの最新指示では通常は未加工で録画し、再エンコード処理のアプリ実装は後回し、現在は FFmpeg コマンドのみ記載する。
4. **録画の不具合**: 2026-10-27 の撮影5本は WAV の PCM が全バイトゼロだった。再接続後の USB 2.0・UVC＋AudioRecord の試験では非ゼロ音声を取得した。撮影時の無音の原因は不明。アプリは長時間完全ゼロの場合の警告と録音状態ログを追加済み。Android の入力抑制を人為的に再現し、警告とログの変化を実機で確認した。
5. **長時間映像**: 19:36:48 の録画は約178.82秒、HEVC 2048×1512、10,624映像パケットで、raw と MP4 の VCL NAL は全数一致。ただし当日の WAV は全ゼロ。FFmpeg の raw HEVC と MP4 の両方のデコード中に `Could not find ref with POC` / `Error constructing the frame RPS` 等が検出され、少なくともこのファイルを「デコードエラー0」とはできない。下部ブロックノイズが全フレームで解消したことも未証明。短い旧検証動画でエラー0だった結果と混同しない。
6. **PTS/DTS**: 上記 MP4 の映像 PTS は 90 kHz 時間基準で全10,624パケット単調増加、同値0。通常の FFmpeg null 出力では DTS 警告が出たが、元ファイルの PTS 重複とは限らず、検査出力の時間基準への丸めを含め切り分ける。`+100 µs` への変更を原因確定前に自動適用しない。
7. **現在の場所・Git・APK**: 作業場所は `C:\Users\kouki\3D Objects\XREAL`。ローカル Git は初期化済みで、録画データ・鍵・会話ログ・`HANDOFF.md` は除外。Git remote は未設定。GitHub の private repository は存在したが、取得できた既定ブランチ名は空で、Actions・Release の成功を意味しない。`build/xreal-recorder.apk` は10月21日の旧ビルドで、端末には10月27日の音声診断変更を含む別ビルドをインストール済み。バージョン名だけでは区別できない。
8. **実機操作**: `HANDOFF.md` の「録音前に他アプリを force-stop」は過去の試験手順であり、他アプリを毎回無条件に停止する必要性やユーザーの包括的な許可を示さない。実機の接続時は SSH / adb と、ユーザーが提示した FTP を利用できるが、実際の接続状態を確認する。既知のカーネルフリーズを伴う usbfs UAC claim/release は再試行しない。

## 元の依頼から落としやすい未完了事項

- **追加キュー（2026-10-27 ユーザー指示）**: XREAL マイクの RAW 取得を調査し、左右独立のステレオ以上、可能であれば独立4chの取得を目指す。現在の WAV は AudioRecord の USB 2ch PCM 保存であり、L/R 一致が観測されているため、物理マイク個別の RAW と見なさない。SDK、UVC/UAC 以外の経路、公開情報と取得できる証拠を優先して検討し、必要な権限と各経路の制約を記録する。未検証の設定変更や危険な usbfs UAC claim/release は行わない。
- 1分超だけでなく10分・30分・60分の段階的録画、映像欠落・A/V内容同期とドリフト・USB再接続・保存容量・電池・温度の評価。現行アプリでこれらを完了した証拠はない。
- 独立2ch / 4chの可否と制約の所在、既存 UVC アプリの録画時パススルー検証、UVC 以外の圧縮映像経路と UVC/UAC 以外の音声経路の比較。
- AOSP Presentation による物理外部画面の検証。未公開の場合は仮想ディスプレイや DeX を使って代替しない。
- 高解像度の実フレームレート60fps、再エンコードなし、1分超の映像と音声を同時に満たすこと。約59.4fpsという結果は測定値として記載し、「常に厳密に60fps」と断定しない。
- Android 側の CPU/GPU・コーデック稼働・発熱・電池、およびグラス給電を含む省電力比較。1ch AAC と 32-bit stereo WAV sidecar の現状は、独立ステレオや4ch保存の達成とは別。
- GitHub Actions でのビルドと Release APK の公開・実機検証。ローカル Git 初期化と私有リポジトリの存在だけでは未達。

詳細な最新の実測、手動 FFmpeg コマンド、未解決事項は `docs/20261027-investigation.md` を参照する。過去の数値・日時・ファイルパスは証拠の時点として扱い、現在の状態を再確認する。

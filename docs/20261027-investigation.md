- スマートフォン上の XREAL 1S の sysfs speed は 480 Mbps。これは調査時の値であり、撮影時のログではない。
- 19:36:48 の MP4 は HEVC 2048×1512 と AAC 48 kHz モノラルを含む。AAC は無音。
- 同じ録画の WAV は 48 kHz、32-bit、ステレオ、8,496,000 フレーム。全 16,992,000 サンプルがゼロ。従って AAC 変換以前の PCM が無音。
- 過去の 10月21日 final3 と p16 の WAV の冒頭5秒には非ゼロのサンプルが存在。既存の実装計画書は p16 の UVC と音声の同時取得を USB 2.0 High Speed で成功したと記録している。USB 2.0 の使用だけを無音の原因とは断定できない。
- 調査時は Android が XREAL USB headset の入力を認識、RECORD_AUDIO は許可、dumpsys audio の mic mute は false。撮影時の状態は不明。
- 19:36:48 のフレームには右端の縦帯と右下の緑線が見える。過去の右端32列が次の行の先頭に似るという測定は、左へ32pxずれたという観察を否定するものではない。クロップで失われた領域が復元されるかは未検証。

## 追加調査（23:12 JST）

- 既存の検証アプリ jp.xreal.artest で、映像を開始せず、同じ USB 入力を AudioRecord UNPROCESSED・48 kHz・2ch・32 bit で3秒取得。USB headset にルーティングされ、144,000フレーム、peak 4,980,736、RMS 129,118.4、ゼロ読み取りなし。撮影時と現在の環境は異なるため、原因は依然未確定。
- 19:36:48 の30秒時点のフレームでは、右端32列と左端の行オフセット比較は +1 行が最小（重み付き平均差 6.101、同一行 6.833）。x=2015/2016 の隣接差 52.865、x=2047/0 は 28.003、x=31/32 は 1.727（RGB平均絶対差）。単純な行内32px循環移動は大きな継ぎ目を x=32 に移すため、この測定はその修復を支持しない。
- アプリに、10秒連続の完全ゼロ PCM バッファを通知する警告を追加。検出は完全ゼロに限るが、静かな環境でも長い完全ゼロ区間が起きうるため、警告だけでは故障を断定できない。録画は停止せず、非ゼロが戻れば警告解除。警告が発生した録画は保存完了時にも表示。Java コンパイルと検出器の閾値・回復テストを実施。実機での警告表示は未検証。

## 追加調査（23:16–23:20 JST）

- 19:36:48 の録画の raw HEVC と MP4 の VCL NAL は 10,624個すべて一致。先頭フレームの YUV hash も一致するので、画像の異常は MP4 格納以前から存在する。
- 同録画の SPS を ffmpeg hevc_metadata で右32pxクロップした比較ファイルは 2016×1512、元の VCL NAL 10,624個と完全一致。縦帯と右下の緑線は表示範囲から外れるが、左側に本来あるべき画像の復元は証明できない。元ファイルは変更していない。
- ユーザーが UVC を有効化して再接続後、sysfs で 480 Mbps・11 interfaces を確認。元アプリで約18秒撮影した 23:16:49 の WAV は 792,000フレーム中、左右合計で非ゼロ 442,954 サンプル、最大絶対値 29,425,664。映像と音声が USB 2.0 で同時取得できることを今回も確認。
- 23:18:15 の録画では開始約4秒後に画面を消灯し、約16秒後に復帰。操作座標の変化により予定時刻の停止に失敗したが、アプリ UID から通常の STOP intent を送って停止した。実録音 52.5秒中、非ゼロ 434,456 サンプル、最大絶対値 46,923,776。消灯中と考えられる区間にも非ゼロがあるが、各区間と電源状態の正確な時刻対応は未取得。静かな状況では長いゼロ区間もあるため、10秒警告は診断用であり、録音障害の証明ではない。
- 追加警告を含む APK は別の一時ディレクトリでビルドし、既存の署名で端末に更新インストールした。元の build ディレクトリは変更していない。実機での警告表示の確認には画面ロック解除が必要。
- 本来の撮影分5本（19:36:48、19:40:47、19:48:22、20:03:40、20:08:28）の各 WAV について、44バイトのヘッダを除く全 PCM バイトを端末上の /dev/zero と比較し、5本とも全バイトがゼロと確認した。後の試験で音が戻ったことは再接続などと関連する可能性を示すが、同時に複数の条件が変化しているため因果関係は未確定。

## 継続調査（23:21–23:24 JST）

- 警告追加版で20.5秒の WAV を録画し、984,000フレーム中、左右合計 70,792 サンプルが非ゼロ（最大絶対値 2,883,584）。この試験では10秒連続ゼロの警告は発生せず、実機で警告表示自体は未検証。

# Android TCP 録画の実機試験（2026-10-30）

- XREAL 1S を接続した SC-52B の USB Ethernet `169.254.2.10` を使用。データ接続は前回測定で USB 2.0 High Speed（480 Mbps）。ケーブルの規格とは区別する。
- `VID_0001.mp4` は 21.980 秒の HEVC 1280×720、657 フレーム、映像 16,720,389 bps、モノラル AAC 128,000 bps。映像と音声の実効時間はそれぞれ 21.980 秒、20.544 秒。先に映像を開始してから音声を開始する実装のため、開始時の音声欠落を含む。音声と映像の同期精度は未検証。
- 画面の表示上は受信中約 30 fps、16 Mbps。録画中に `XrealRec:record` の partial wake lock を確認し、停止後に解除を確認した。省電力の対象外設定も確認した。長時間の新実装検証ではない。
- 最初の保存では Android が DCIM 以下への JSON ファイル作成を拒否した。MP4 自体は保存された。修正後の `VID_0002` では MP4 を `DCIM/100XREAL`、付随情報を `Documents/XREAL/100XREAL` に保存できた。任意フォルダーの保存は未検証。
- TCP 30 fps と UVC HEVC 60 fps は選択欄に表示。MJPEG の 30 fps / 60 fps は Windows で実映像を取得済みだが、Android アプリへの実装と検証は未完了。選択できるようになるまでは利用可能と扱わない。
- XREAL 外部画面の固定・サイド表示の見え方、画面消灯状態での新実装の長時間録画、映像・音声の同期、実際の USB 2.0 ケーブルでの検証は未完了。

## TCP の音声開始と第2画面

- TCP 録画では音声開始前の固定 2 秒待ちを外し、`VID_0003.mp4` で音声開始 0.000 秒、映像開始 0.7674 秒を確認した。開始時に音声が映像より短くなる問題はこの短い試験では解消したが、厳密な音画同期と長時間安定性は未検証。UVC の開始順序は従来の実績を維持している。
- 同ファイルの AAC 音声は平均 -91.0 dBFS、最大 -62.7 dBFS と非常に小さかった。試験時の周囲音量は未記録で、原因や通常使用での音量は未確定。音声トラックの存在だけでは十分な音が録れている証明にならない。
- 無音検出は従来、AAC へ渡す前のステレオ 32-bit 全体を判定していたため、実際に保存する左チャンネル 16-bit が無音でも警告しない場合がある。保存するモノラル PCM のゼロを判定するよう修正した。小さな非ゼロ音は検出対象外。
- 修正版を実機で録画したところ、USB 音声のルーティングを確認し、連続ゼロの警告が発生・解除された。音声の可聴性を確認した結果ではない。
- Android の外部ディスプレイ ID 9 上に Presentation が生成され、XREAL 1S の物理ディスプレイのキャプチャで黒背景の録画中表示、経過時間、受信レート、音声状態を確認した。固定表示・サイド表示それぞれで装着者からの見え方は未確認。

## USB 音声の追加調査

- 同時録画時の AudioRecord 入力を診断用 WAV に保存し、32-bit ステレオの 360,000 フレーム（7.5 秒）を調べた。左右は全フレーム一致し、前半 1 秒のうち 5,229 フレームのみ左 16-bit が非ゼロ、残り 6.5 秒は両チャンネルとも 32-bit 全ビットがゼロだった。USB マイクにルーティングされていても、入力そのものが途切れる場合がある。今回の無音部分について AAC 変換が原因とは言えない。
- 警告を 10 秒から 3 秒の連続ゼロに変更。静かな環境でもゼロが続く可能性はあるため、原因断定ではなく確認を促す警告として扱う。非ゼロで非常に小さな音や実際の可聴性は判定できない。
- 根本原因、周囲音のある条件での入力動作、長時間の再発率は未解明。危険性が確認された UAC の直接取得は行っていない。
- ユーザーが近くで音を流し続けたと報告した際の TCP 録画 `VID_0006.mp4`（約41秒）を取得。AAC 全体の平均は -60.1 dBFS、最大は -24.5 dBFS。-60 dBFS 以下が約 16.15 秒続く区間があり、入力が十分に録れたとは確認できない。再生開始時刻や元音源は未記録のため、その区間と再生時間との対応は不明。3秒の完全ゼロ警告はこの録画中に出ておらず、微小な非ゼロ信号は警告から漏れる。
- この見落としを減らすため、保存対象の 16-bit モノラル PCM が連続 3 秒にわたって各サンプル絶対値 32 以下（約 -60 dBFS）なら「非常に小さいか無音」と警告する。通常の静かな場面でも表示され得るため、故障の断定には使わない。音量を変更せず、短い大きな音が入ると判定時間をリセットする。合成 PCM で発生・解除・閾値をテスト済み、実機検証は別途必要。
- 録音データが連続 3 秒すべてゼロの場合と、ゼロではないが非常に小さい場合を別表示にした。スマートフォンと XREAL の画面に、保存対象音声のピーク履歴と REC・経過時間を表示する。履歴は波形の振幅の概形で、音声信号を変換・増幅して保存するものではない。
- XREAL の画面配置を固定表示用（右上）とサイド表示用（右側中央）から録画前に選択できる。固定表示用は物理ディスプレイのキャプチャで右上配置を確認した。装着状態の固定・サイド双方の見え方、サイド表示用の実機キャプチャ、物理 USB 2.0 ケーブルでのスマートフォン単独表示は未検証。

## TCP の約3分録画

- `VID_0007.mp4` は映像 194.709 秒、5,812 フレーム、平均 17.043 Mbps。映像パケットの PTS は全て単調増加し、最小間隔 1.822 ms、最大 64.833 ms、100 ms 超はなかった。到着時刻を使うため間隔にばらつきがある。
- FFmpeg で全映像を復号し、出力側の時間基準をマイクロ秒にして実行した結果、エラー出力なし。出力側を既定のフレーム時間基準にすると時刻の丸めで null muxer の DTS 警告が出るが、元ファイルの PTS 自体は逆行していない。
- これは短時間の録画・復号検証であり、撮影時の全フレーム受信、音画同期や無音の不在、長時間の安定性を証明しない。消灯中の別録画は引き続き試験中。

## TCP の消灯中10分録画

- `VID_0009.mp4` は消灯状態で約10分間実行し、通常停止と共有ストレージへの保存を確認した。HEVC は 626.554 秒、18,701 フレーム、平均 17.072 Mbps、AAC は 627.051 秒、128 kbps。映像 PTS は全て単調増加、隣接間隔は 1.311〜62.989 ms、100 ms 超なし。
- USB 音声は平均 -82.5 dBFS、最大 -47.4 dBFS。録画開始後に低レベル警告が発生した。試験中の周囲音は記録していないため、音声経路が故障しているかどうかは断定できず、十分な音声が得られたと見なせない。
- 全映像を FFmpeg で復号し、出力側の時間基準をマイクロ秒にした検査でエラー出力なし。TCP の最新の映像受信停止検出はこの録画で検証していない。映像の到着時刻を使うため音画同期の精度も未検証。
- TCP 映像が 5 秒受信できない場合にエラーとする処理を追加。ローカル TCP 通信の試験では、分割受信の結合と受信停止時の期限切れを確認した。更新版アプリで通常録画・停止と `VID_0010.mp4` の保存を確認。実機のカメラ接続を途中で切断した試験は行っていない。
- システムのフォルダー選択で `Documents/XREAL_Recorder_Test` を指定し、TCP 録画を正常停止した。選択先に `VID_0001.mp4` と同名 JSON が保存され、MP4 は HEVC 537 フレーム・17.995 秒と AAC 870 フレーム・18.560 秒を FFprobe で確認した。テスト後は保存先表示が標準の `DCIM/100XREAL` に戻った。他のストレージプロバイダーには一般化できない。
- ユーザーが XREAL を再接続した後の TCP 録画 `VID_0014.mp4` は HEVC 688 フレーム・23.044 秒・16.979 Mbps、AAC 23.552 秒。USB マイクへのルーティングと `systemSilenced=false` を確認したが、3 秒後に低レベル警告が発生し、AAC の平均は -87.3 dBFS、最大 -48.9 dBFS。周囲音の条件は記録しておらず、機器や設定の原因は特定できない。
- 別の実機録画 `VID_0011.mp4` では診断保存を一時的に有効化し、TCP から受信した HEVC と MP4 から無変換抽出した HEVC の VCL NAL を比較した。1,358 個すべて順序・内容が一致し、再エンコードや保存時の VCL 欠落は確認されなかった。MP4 抽出側の VPS/SPS/PPS 追加はコンテナ復元によるもの。比較後、診断用の別保存設定はオフに戻した。カメラから受信前の欠落や別録画での欠落はこの比較だけでは判定できない。
- 同録画の診断 WAV（46 秒）は全フレームで左右一致し、左チャンネル 2,208,000 サンプル中 291,857 個が完全ゼロ。WAV の平均・最大レベルは -81.3 / -47.4 dBFS、MP4 の AAC は -81.3 / -47.5 dBFS で、この録画の低レベルは AAC 保存以前から生じている。音の再生条件は記録していないため、無音環境と機器側の入力不調は区別できない。
- スマートフォンの音声履歴表示が更新時点の短い PCM 断片だけを参照していたため、間に発生した短い音を見落とし得た。次の画面更新までの最大値を蓄積して表示するよう修正。ビルド・インストールを確認し、実音を使った画面検証は未実施。
- 同期の調査用に、TCP 映像ヘッダー offset 24 の未確認時刻候補と受信時刻の経過差を集計した。過去の10分バイナリでは 17,884 フレームの候補値は単調増加し、隣接差は 33.469〜33.539 ms。新たな Android 実機録画では 1,000 フレーム、候補値の経過 33.469873 秒、受信時刻の経過 33.466685 秒、先頭基準の経過差の最大絶対値 15.098 ms、逆行 0。この値の仕様・実際の露光時刻・音声との時計対応は未確認のため、保存 PTS は引き続き受信時刻を使う。

## MJPEG 音声付き保存の開発

- JPEG 画像と 48 kHz モノラル AAC の合成データを Matroska に保存し、FFprobe で映像 30 フレームと音声 48 フレームを認識、FFmpeg で両方をエラー出力なく復号できた。JPEG は再エンコードしていない。
- Android の録画コンテナ処理を追加したが、実機カメラ取得・アプリ UI には未接続。実機での 30/60 fps 録画、音声同期、長時間安定性は未検証であり、利用可能な機能とは扱わない。

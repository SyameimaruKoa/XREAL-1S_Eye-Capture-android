# Android TCP 録画の実機試験（2026-10-30）

- XREAL 1S を接続した SC-52B の USB Ethernet `169.254.2.10` を使用。データ接続は前回測定で USB 2.0 High Speed（480 Mbps）。ケーブルの規格とは区別する。
- `VID_0001.mp4` は 21.980 秒の HEVC 1280×720、657 フレーム、映像 16,720,389 bps、モノラル AAC 128,000 bps。映像と音声の実効時間はそれぞれ 21.980 秒、20.544 秒。先に映像を開始してから音声を開始する実装のため、開始時の音声欠落を含む。音声と映像の同期精度は未検証。
- 画面の表示上は受信中約 30 fps、16 Mbps。録画中に `XrealRec:record` の partial wake lock を確認し、停止後に解除を確認した。省電力の対象外設定も確認した。長時間の新実装検証ではない。
- 最初の保存では Android が DCIM 以下への JSON ファイル作成を拒否した。MP4 自体は保存された。修正後の `VID_0002` では MP4 を `DCIM/100XREAL`、付随情報を `Documents/XREAL/100XREAL` に保存できた。任意フォルダーの保存は未検証。
- TCP 30 fps と UVC HEVC 60 fps は選択欄に表示。MJPEG の 30 fps / 60 fps は Windows で実映像を取得済みだが、Android アプリへの実装と検証は未完了。選択できるようになるまでは利用可能と扱わない。
- XREAL 外部画面の固定・サイド表示の見え方、画面消灯状態での新実装の長時間録画、映像・音声の同期、実際の USB 2.0 ケーブルでの検証は未完了。

## TCP の音声開始と第2画面

- TCP 録画では音声開始前の固定 2 秒待ちを外し、`VID_0003.mp4` で音声開始 0.000 秒、映像開始 0.7674 秒を確認した。開始時に音声が映像より短くなる問題はこの短い試験では解消したが、厳密な音画同期と長時間安定性は未検証。UVC の開始順序は従来の実績を維持している。
- 同ファイルの AAC 音声は平均 -91.0 dBFS、最大 -62.7 dBFS と非常に小さかった。試験時の周囲音量は未記録で、原因や通常使用での音量は未確定。音声トラックの存在だけでは十分な音が録れている証明にならない。
- 無音検出は従来、AAC へ渡す前のステレオ 32-bit 全体を判定していたため、実際に保存する左チャンネル 16-bit が無音でも警告しない場合がある。保存するモノラル PCM のゼロを判定するよう修正した。小さな非ゼロ音は検出対象外。
- 修正版を実機で録画したところ、USB 音声のルーティングを確認し、連続ゼロの警告が発生・解除された。音声の可聴性を確認した結果ではない。
- Android の外部ディスプレイ ID 9 上に Presentation が生成され、XREAL 1S の物理ディスプレイのキャプチャで黒背景の録画中表示、経過時間、受信レート、音声状態を確認した。固定表示・サイド表示それぞれで装着者からの見え方は未確認。
